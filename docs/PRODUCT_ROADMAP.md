# RGP: дорожная карта после перехода на читаемый RGP/0.1.0

**Актуализирована:** 31 октября 2026 года. **Канонический план:** три этапа.
**Решение:** основной формат — один текстовый `REPO_CONTEXT.rgp` версии
**RGP/0.1.0**, а не ZIP, Base64, sidecar или обязательный GitHub Actions artifact.
Технический аудит текущей реализации: [REVIEW_2026-10-31.md](REVIEW_2026-10-31.md).
Критерий продукта: [PRODUCT_NORTH_STAR.md](PRODUCT_NORTH_STAR.md).

## Для чего RGP существует

RGP помогает Кире выполнять **настоящие GitHub-задачи**: видеть структуру
репозитория, ориентироваться в исходниках, находить тесты и безопасно
вносить изменения. RGP — только **read-only контекст**, не редактор,
не замена Git и не доказательство корректности ответа модели.

Приоритетный сценарий: прочитать небольшой заголовок и индекс RGP через
GitHub-коннектор → запросить **только нужные диапазоны строк** →
выяснить изменения и связанные тесты → исправить сам GitHub-проект →
проверить тестами и CI. Если нужен **полный доверенный файл**, загрузить
его как файл (без протаскивания текста через модель), удостоверить по
независимому Git blob или внешнему SHA-256 и сверить исходники с
закреплённым Git-коммитом. Нельзя выдавать структурную проверку Reader
за проверку подлинности RGP/0.1.0.

### Зафиксированная новая архитектура

| Аспект | Основной путь |
| --- | --- |
| Транспорт | UTF-8, короткая инструкция, табличный индекс, исходный текст |
| Файлы | Оригинальные UTF-8 байты, точные границы через длину в байтах |
| Ненужные пути | Отфильтрованы закреплённым `.rgpignore`, доступны в Git по требованию |
| SHA-256, Git SHA, JSON-манифест | **Не пишутся** в RGP/0.1.0 ради токенов |
| Происхождение/доверие | Git-ревизия и контрольная сумма **вне файла** |
| Чтение | GitHub line-range запросы; локальный Reader только если файл действительно получен |
| GitHub Actions ZIP | Необязательный способ доставки; не определяет формат |
| Старые форматы 1.x / 2.x / 3.0 | **Не поддерживаются**; Reader и verifier принимают только 0.1.0 |
| Индексы, MCP, граф | Не обязательны; создавать только после измеренной потребности |

`snapshot_complete` отражает **выбранный объём** после `.rgpignore`,
а не весь Git-репозиторий. В RGP/0.1.0 отсутствуют путь-специфичные
доказательства всех проигнорированных файлов: в индексе хранится
их количество и сам `.rgpignore`. Без внешнего Git-сверения изменения
исходника той же длины Reader не выявляет. Это **сознательный компромисс**,
который нужно явно предъявлять агенту и пользователю.

## Этап 1. Минимальный надёжный контекст и доказательство ценности

**Статус: выполняется. Gate B = HOLD.**

**Уже есть:**
- RGP/0.1.0: текст без ZIP/Base64 и без технических SHA-полей; один файл;
  `.rgpignore`; детерминированный генератор и Reader.
- Reader поддерживает только RGP/0.1.0 без legacy fixtures.
- Проверки Rust/Python, негативные сценарии, закреплённые корпуса,
  стресс-тесты и тест границы 50k. Это свидетельствует о
  **технической работоспособности**, но не о пользе для модели.
- Локальные MCP и sandbox-интерфейсы как опциональные адаптеры.

**Нужно довести:**
- [ ] Протестировать доступ агента к заголовку, индексу и **точным
  строковым диапазонам** через имеющийся GitHub-коннектор. Для двух-трёх
  небольших репозиториев записать, где запросы из RGP быстрее и где
  прямой `fetch_file` оказывается проще.
- [ ] Привести весь конвейер к общему **внешнему trust anchor**:
  фиксированный исходный Git SHA, Git blob опубликованного RGP,
  при необходимости отдельный full-file SHA-256. Указывать, какие
  звенья цепи не проверены. Файл сам себя не аутентифицирует.
- [ ] Измерить реальные **токены**: основной вывод в модель, долю
  служебных строк, число чтений и расход контекста. Сам по себе
  размер в байтах не является измерением токенов.
- [ ] Обновить негативные тесты для RGP/0.1.0: неверные длины,
  неожиданные delimiters, UTF-8, опасные пути, подмену длины;
  **явно тестировать**, что равнодлинная подмена не обнаруживается
  без Git, и обеспечить её отбраковку в доверенном потоке.
- [ ] Выполнить независимый, ослеплённый **Gate B**: те же
  12 зафиксированных задач и новые незнакомые задачи, RGP и
  GitHub-only с честным кешированием, оценка человеком/внешней
  процедурой корректности и полной стоимости. Старые наблюдения
  остаются историческим baseline, не доказательством RGP/0.1.0.
- [ ] Отдельно проверить ограничения безопасной публикации:
  чувствительные файлы, подмодули, LFS, изменения `.rgpignore`,
  неполные снимки и ошибочные утверждения об актуальности.

**Критерий закрытия:** воспроизводимый Git→RGP/0.1.0→выборочный
контекст→проверенные решения задач; известные отрицательные кейсы
закрыты; независимый Gate B даёт обоснованный **GO**. Пока результатов
такого теста нет, **HOLD**, даже если весь CI зелёный. Не расширять
масштабирование или формат ради самих бенчмарков.

## Этап 2. Реальные изменения кода и индекс только при необходимости

**Зависимость:** Gate B подтвердил, что отобранный контекст помогает.

- [ ] Кира выполняет реальные PR: сначала читает RGP/0.1.0
  выборочными фрагментами, затем меняет **GitHub-репозиторий** и
  запускает тесты; сравнить с эквивалентным GitHub-only baseline.
- [ ] Измерить ошибки, повторные правки, полноту выбранных тестов,
  GitHub-вызовы, время и **токены**; отдельно считать подготовку,
  обновление и загрузку RGP.
- [ ] Определить, достаточно ли перечня путей и лексического поиска.
  Если нет, добавить минимальные `symbols/definitions/references`
  с точными `path:line`, `parsed/partial/unsupported` и
  доказуемым происхождением.
- [ ] `dependencies/impact` строить только из подтверждённых
  связей и нужных проекту языков. Не принимать упоминания за
  реальный граф вызовов.
- [ ] Зафиксировать границы stale-снимков, работу с исключёнными
  файлами и fallback при отсутствии RGP.

**Критерий:** на честных задачах реальной разработки корректность
не хуже GitHub-only и измерены цена/выигрыш. Без пользы от индекса
**PIVOT** к простому текстовому Reader, без навязывания графа.

## Этап 3. Эксплуатация, безопасность и выпуск

**Зависимость:** этап 2 подтвердил нужный сценарий и интерфейс.

- [ ] Зафиксировать политику дальнейшего версионирования CLI и Reader
  после RGP/0.1.0 без восстановления старых транспортов.
- [ ] Автоматическое обновление Git-tracked RGP с атомарной
  публикацией, подтверждением Git blob и проверкой актуальности.
- [ ] Определить политику разрешённых публикаций, работу с
  приватными репозиториями, ограничениями коннектора и секретами.
- [ ] Ограничения ресурсов и security-регрессии: большие пути,
  NUL/UTF-8, границы байтов, повторные записи, необнаружимые
  без внешнего якоря подмены; отдельно проверять лимиты
  необязательной ZIP-обёртки доставки, не смешивая её с форматом RGP.
- [ ] Честная эксплуатационная диагностика и восстановление при
  недоступном файле или частичном RGP.
- [ ] Полный release rehearsal на фиксированном Git-коммите,
  включая внешнюю проверку подлинности и результат настоящей
  пользовательской задачи; затем только объявлять v1.0.

**Критерий релиза:** полезность доказана, trust boundary проверен,
нужные регрессии зелёные, известные ограничения опубликованы;
нет подмены измеренных токенов уменьшением размера в байтах.

## Что не нужно переносить в новый основной путь

Ранние ZIP/Base64-транспортные PoC и старые отчёты о сжатии описывают
**историю разработки**, но не действующий продуктовый формат.
Сырые замороженные Gate B-наблюдения, протокол независимой проверки,
план задач и отчёты оставлены как исторический аудит, **не как
обязательство обратной совместимости**. Старые транспортные fixtures
и реализации удалены; при необходимости доступны в Git history.

**Правило доказательности:** фиксировать конкретные коммиты,
исходный Git, CI/exit code, модельные токены (если они действительно
измерены), ошибки и ограничения. Никогда не выдавать отсутствие
проверки за нулевую стоимость или успешный результат.
