# RGP как локальное дерево исходников в песочнице Киры

**Кому это нужно:** Кире, coding-ассистенту ChatGPT, которая меняет
GitHub-проекты и хочет понимать исходный код в своей Python-песочнице.
[Каноническая цель RGP](PRODUCT_NORTH_STAR.md) важнее самого формата ZIP.
Этот интерфейс позволяет использовать обычные Python/grep/file-tools,
а не обращаться к Reader отдельно за каждым файлом.

## Пример использования настоящего GitHub Actions RGP

После получения RGP из поддерживаемого GitHub-канала и **независимой
проверки эталонного SHA-256** (например, замороженное значение в Git,
а не SHA из того же недоверенного ZIP):

```sh
# Вызов из доверенной локальной копии RGP Python-утилит:
python3 python/rgp_sandbox.py \
  --artifact /mnt/data/REPO_CONTEXT.rgp \
  --trusted-sha256 <sha256-from-separate-trusted-source> \
  --expected-commit <GitHub-commit-SHA> \
  --output /mnt/data/my-source-workspace

# После успешной команды можно работать с исходниками как с файлами:
python3 - <<'PY'
from pathlib import Path
root = Path("/mnt/data/my-source-workspace")
for p in sorted(root.rglob("*.py")):
    print(p.relative_to(root))
PY
```

Для локальной задачи по конкретному модулю доступен
`--prefix src/`. По умолчанию экспорт ограничен **1000 файлами
и 32 MiB исходных байтов**, что соответствует целевому масштабу
наших проектов. Бюджет можно явно поднять опциями `--max-files`,
`--max-bytes` (верхняя граница 128 MiB). Нельзя без предупреждения
пропустить файлы: превышение бюджета завершает команду ошибкой.

## Отказ от старого, хотя и целостного снимка

**`--expected-commit` обязателен**. Перед работой с кодом Кира
отдельно получает из GitHub точный commit, который собирается
анализировать и изменять. Даже полностью валидный и аутентичный
RGP от другого Git-коммита будет отвергнут с `STALE_SNAPSHOT`,
**без создания рабочей папки**. Это практический риск, обнаруженный
в песочнице: локальный архив `iivkis/rgp@95963a23` оставался
целостным после того, как `main` перешёл к новым ревизиям.

Утилита проверяет **равенство переданному SHA**, но сама не
проверяет актуальный GitHub HEAD. Перед отправкой правки нужно
проверить HEAD ещё раз; GitHub-ветка могла обновиться в процессе
работы. При намеренном анализе исторического коммита указывают
именно этот старый коммит, а не `HEAD` строкой.

## Происхождение и безопасность

Утилита:

1. Требует **внешний доверенный SHA-256** и сравнивает его с
   реальными RGP-байтами *до* разбора.
2. Проверяет весь RGP/1.0 с помощью доверенного Python stdlib Reader,
   включая содержимое и манифест. Неполный снимок отклоняет, если
   `--allow-partial` не выбран **явно**.
3. Использует публичный `Reader.read_bytes(path)`, не зависящий от
   внутреннего способа хранения ZIP; он возвращает точные Git-байты,
   в том числе бинарные файлы и окончания строк. Экспортирует файлы
   в **новую** отдельную папку. Существующую
   директорию не меняет, в случае неудачи очищает временную область.
   ZIP путями управляет проверенный Reader, вложенные `../`
   и абсолютные пути не поддерживаются.
4. Создаёт только **обычные файлы без исполняемых битов**.
   Git-симлинки записываются *текстом ссылки*, никогда не
   преобразуются в реальные симлинки.
5. Записывает `.rgp-sandbox.json` с исходным и ожидаемым commit,\n   честным статусом сравнения (но не сетевой проверкой HEAD), хешем,
   неполнотой, числом файлов, байтами и предупреждениями
   о симлинках/LFS. Это provenance, не разрешение доверять
   комментариям в коде.

**Важно:** локальная папка с исходниками **не является Git worktree**
и не изменяет репозиторий GitHub. Она нужна только для понимания,
поиска и анализа. Изменения нужно отправлять через GitHub или
отдельную рабочую копию Git, проверяя актуальность исходного commit.
Нельзя исполнять scripts/тесты/модули, извлечённые из недоверенного
снимка, без отдельной проверки их безопасности.

## Продуктовая приёмка

[Реальный CI](../scripts/stage1_sandbox_task_trial.py) создаёт
проверенный RGP из трёх закреплённых Git репозиториев с 46, 93 и 50
файлами и отдельно сверяет **все** файлы локального экспортированного
дерева с `git show <commit>:<path>`. Отдельные unit-тесты проверяют
неверный хеш, неполный снимок, существующую папку, symlink и
executable бит, лимиты и отсутствие осиротевших файлов после ошибки.
В артефактах CI публикуются только метаданные.

Это полезное средство **dogfooding RGP внутри песочницы**, но
побайтная проверка экспорта ещё не означает автоматически, что
Кира реже ошибается при реальной GitHub-правке. Следующая задача
после выпуска: взять незнакомое исправление в одном из небольших
проектов, изучить его через эту папку, изменить исходники через
GitHub и проверить регрессии. Сравнить честно с baseline без RGP.
**Gate B остаётся HOLD**.
