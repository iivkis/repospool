# Практическое подключение RGP к coding-агенту через MCP

Экспериментальная интеграция этапа 2. Вместо ручного импорта Python Reader
модель получает пять локальных read-only инструментов MCP (stdio JSON-RPC).
Исходный архив должен быть предварительно проверен по внешнему SHA-256.

## Пример настройки MCP-клиента

Следующая структура `mcpServers` поддерживается многими MCP-клиентами;
конкретное место настройки зависит от клиента:

```json
{
  "mcpServers": {
    "rgp-source": {
      "command": "python3",
      "args": [
        "/absolute/path/to/rgp/python/rgp_mcp.py",
        "--artifact",
        "/absolute/path/to/REPO_CONTEXT.rgp"
      ]
    }
  }
}
```

Сервер использует только Python stdlib, не открывает сетевой порт,
не загружает исходники из сети и никогда не исполняет код из RGP.
Сначала проверяет снимок доверенным Reader. Неисправный RGP
вызывает ошибку запуска. Вывод stdout содержит только MCP JSON-RPC.

## Инструменты

| Инструмент | Для чего |
| --- | --- |
| `rgp_status` | Исходный commit, полнота и отсутствие семантического индекса |
| `rgp_tree` | Постранично перечислить файлы |
| `rgp_search` | Искать буквальные совпадения в исходных строках |
| `rgp_read` | Получить точный диапазон строк конкретного пути |
| `rgp_context` | Собрать ограниченные цитируемые фрагменты по 1–6 словам |

Рабочий цикл агента: сначала status, затем context по выбранным
им терминам, затем search/read для уточнения и ответ с цитатами
`path:start_line-end_line` на закреплённом Git commit.
Отсутствие результатов не доказывает отсутствия кода в репозитории.
Учитывать `terms_without_source`, `search_capped_terms` и `selection_truncated`.

Содержимое исходника остаётся недоверенными данными. Комментарии
из ZIP не должны становиться системными инструкциями модели.
Сервер не предоставляет shell, exec, изменения файлов или Git-доступ.
При ответе больше 64 KiB возвращается ошибка, а не тихое усечение.

## Настоящий end-to-end тест

Скрипт `scripts/stage1_mcp_agent_trial.py` запускает независимый
процесс MCP, делает initialize/tools/list и четыре source-задачи
на каждом из трёх закреплённых Git-репозиториев с 46/93/50 файлами.
Каждую цитату сверяет с оригинальным Git show, дополнительно вызывает
rgp_read и rgp_search, проверяет отказ на пути вне снапшота.
CI публикует только метаданные: число задач, MCP-вызовов,
байты контекста/ответов и время. В CI нет запуска LLM.

**Принципиальное ограничение:** реальные MCP tool calls и верные
исходники не равны независимо проверенным ответам нейросети.
Тест использует заранее выбранные поисковые термины. Чтобы
объективно измерить пользу, нужны два независимых запуска одной
LLM с GitHub и RGP, подсчёт токенов/времени/вызовов и слепая
проверка ответов. Поскольку отдельной модели для такой проверки
пока нет, Gate B остаётся HOLD, а качество ответа не заявляется.

См. `docs/AGENT_VALUE_TRIAL_2026-10-31.md`: три архива RGP были
тяжелее 13 выбранных исходных GitHub файлов, поэтому экономия
сетевых байтов не доказана.
