# Stage 1: 50,000 ZIP-member boundary, actual CI evidence

Date: 31 October 2026.
Source: [GitHub Actions run 41133164460](https://github.com/iivkis/rgp/actions/runs/41133164460)
on [PR #39](https://github.com/iivkis/rgp/pull/39).

**Observed outcome: PASS.** The developer-owned E2E created a real, new
Git commit containing **50,005 distinct source blobs**. It then generated
two RGPs from the exact pinned Git commit, compared all output bytes,
verified the RGP via Rust and the independent Python Reader, paginated
the entire included tree and independently tested read/search against
raw Git source. No source bytes or RGP artifact were published by CI.

## Precise corpus and result

| Field | Actual result |
| --- | --- |
| Synthetic fixed Git commit | `9e14cbaa68aeee52aa07a009af5274bca619ed47` |
| Input Git files | **50,005** |

| RGP source completeness | **false / partial** |
| Paginated `tree` | **250 complete pages, no duplicates/gaps** |
| Independent pinned source read/search checks | **4/4 PASS** |
| Source files above cap readable from RGP | **No; rejected** |
| Truncated output accepted | **No; rejected** |
| Two generations at same commit byte-identical | **Yes** |

A large source tree does **not** imply a complete snapshot. Every
excluded path is recorded in the manifest. This test establishes the
**50,000 ZIP-member wire limit** in the actual production generator,
verifier and Reader. It does not prove performance at all sizes or
for arbitrary long filenames.

## Observed resource measurements

| Operation | Elapsed | Peak resident memory |
| --- | ---: | ---: |
| Rust generator, first run | **2,710 ms** | **186,980 KiB** |
| Rust generator, second run | **2,550 ms** | **187,004 KiB** |
| Rust verification against original Git | **1,600 ms** | **87,004 KiB** |
| Python Reader full validation | **1,830.467 ms** | Part of Python-process peak below |
| Public Reader tree traversal of 250 pages | **2,819.942 ms** | Part of Python-process peak below |
| Python harness high-water RSS | Not isolated | **234,204 KiB** |

The measurements come from real GitHub Actions commands. Rust wall time
has 10 ms resolution from GNU `time`; Python times use
`perf_counter_ns`. Memory is whole-process RSS, not an incremental
allocation trace. Git fixture creation, checkout transport, network
download, model tokens and connected GitHub tool requests are **not**
included in these timing figures.

The ~183 MiB generator RSS and ~229 MiB Python-process high-water memory
are **not constant-space**. The current generator buffers the RGP ZIP,
transport text and some metadata in memory; a future optimization
should reduce peak memory only with measured before/after evidence and
byte-compatibility checks.
