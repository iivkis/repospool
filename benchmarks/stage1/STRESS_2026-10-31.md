# Stage 1 stress diagnostic: measured evidence (31 Oct 2026)

**Evidence:** [GitHub Actions stress run 41129801781](https://github.com/iivkis/rgp/actions/runs/41129801781),
PR [#36](https://github.com/iivkis/rgp/pull/36).
**Result: 4/4 Git→RGP→Rust verify→Python Reader stress profiles PASS.**
Each profile used a newly created temporary Git repository, fixed commit
metadata, two deterministic RGP generations, independently read Git sources,
and exact byte comparisons. Metadata-only evidence was uploaded by CI.
No third-party source code, generated RGP, or large source blob was uploaded.

## Observed measurements

| 12 MiB incompressible | 1 / true | 17,001,659 | 710 / 109,928 | 100 / 51,508 | 160.938 |
| 12 MiB highly compressible text | 1 / true | 16,998,972 | 210 / 110,424 | 100 / 51,464 | 159.269 |
| 16 MiB + 1 byte oversized blob | 1 README / **false** | 1,072 | 0 / 4,916 | 0 / 4,916 | 4.919 |

0 ms at `/usr/bin/time`'s 10 ms resolution means **below the timing
resolution**, not instantaneous. The per-process RSS and wall time are
observed on separate ephemeral GitHub Actions runners, and should not be
interpreted as a controlled speedup or a production-wide upper bound.
First-generation times exclude source checkout and model/connector transport.

The compressible profile verified that the producer used **exactly one
ZIP_STORED blob**, preserving the anti-zip-bomb ratio rule while making
a 12 MiB repetitive source file available. The incompressible profile
verified no such fallback occurred. For the oversized profile, the
16 MiB + 1 byte file was **excluded** with reason `size_limit`, the
Reader refused to read it, and snapshot completeness was **false**.

The 2,000-file profile verified complete traversal of paginated `tree`
without duplicates or omissions, byte fidelity against Git, and
determinism across two generated RGPs. All profiles also tested rejection
of a truncated version of the **actual created RGP**.

## What is not proven

- These are synthetic, bounded workloads, **not** a 50,000-file stress
  limit, a 128 MiB inflated-size exhaustion proof or an enterprise-scale
  workload.
- They do not measure end-to-end connector transfers, token use,
  independent natural-language answer quality or comparative GitHub cost.
- Peak memory for two 12 MiB cases was around **107–108 MiB**, not
  constant-space. The generator still buffers ZIP content; its memory
  footprint is a real optimization opportunity.
- **Stage 1 product gate and Gate B remain HOLD**, pending independently
  graded task answers, authenticated connector operation history and
  remaining deployment/security proof.
