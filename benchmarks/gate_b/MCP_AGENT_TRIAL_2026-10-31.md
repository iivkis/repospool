# RGP как инструменты coding-агента: реальный MCP E2E

Дата: 31 октября 2026. Продуктовый шаг после 12-задачного опыта
без дополнительных оптимизаций ZIP и без заявлений о качестве LLM.

## Метод

Разработанный агент запустил собственный MCP-клиент как отдельный процесс.
Каждый из трёх runner'ов сгенерировал RGP из точного закреплённого Git
коммита, выполнил Rust/Python проверку и затем по stdin/stdout:

1. Согласовал версию MCP в `initialize` и получил список инструментов.
2. Вызвал `rgp_status` и `rgp_tree` для проверки коммита, полноты и покрытия.
3. Выполнил по 4 заранее закреплённых задания из
   `benchmarks/gate_b/plan.json` через `rgp_context`.
4. Сверил каждую выданную исходную строку с оригиналом `git show SHA:path`.
5. Самостоятельно запросил один диапазон через `rgp_read` и один
   поиск через `rgp_search` для каждого задания.
6. Проверил запрет на чтение `../not-in-repo` и корректное завершение MCP.

Важное ограничение: поисковые термины были предварительно подобраны
по известным задачам. Это не свободный поиск модели и не оценка
правильности ответов нейросети. Модель в этом CI вообще не запускается.

## Что даёт RGP сейчас

- Реальный LLM-клиент с поддержкой MCP может подключить один
  закреплённый и отдельно верифицированный снимок и получать
  проверяемый исходный код через привычный интерфейс инструментов.
- Нет требований к клонированию Git на стороне агента,
  импорту Reader в его runtime или исполнению файлов архива.
- Прямая запись JSON-RPC по stdio не требует отдельного
  сервиса, секрета или сетевого порта.
- Пользователь видит ограниченность: partial snapshot,
  недостающие термины, неполные результаты, отсутствие
  подтверждённых семантических определений/связей.

## Что не доказано

- Сами 12 задач в CI решал **подготовленный скрипт-клиент**,
  а не независимая модель с автономным выбором поисковых запросов.
- 42 вызова MCP являются локальными запросами к Reader и
  **не должны** сравниваться напрямую с 13 GitHub connector calls.
- Качество ответов двух моделей, входные/выходные токены,
  загрузка ZIP, GitHub кеш, полная стоимость и задержки не измерены.
- Сравнительная гипотеза RGP vs GitHub остаётся непроверенной;
  нельзя утверждать, что RGP точнее или дешевле.

## Следующий продуктовый эксперимент

Подключить два *изолированных запуска одной модели* на свежих
вопросах: один с доступом к прямым GitHub source tools и кешем;
второй с этими RGP MCP tools. Сохранить достоверные
tool logs, input/output token usage, time to answer, первичную
стоимость создания/скачивания артефакта. Передать ответы
независимому слепому проверяющему с исходным Git.
