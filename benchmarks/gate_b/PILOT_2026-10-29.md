# Gate B single-session diagnostic: 2026-10-29

**Decision: HOLD pending independent evidence review.** The v2 evaluator
returns `GO_CANDIDATE` on the accompanying
[`observations.pilot_2026-10-29.json`](observations.pilot_2026-10-29.json).
A candidate result is not approval to declare an actual product win.

## Procedure

The assistant in the active chat performed all 12 tasks against the frozen
`benchmarks/gate_b/plan.json` corpus, once through GitHub `fetch_file` at
each pinned Git commit and once through the local stdlib RGP Reader after
downloading the three pinned GitHub Actions ZIP artifacts from run
[40767794459](https://github.com/iivkis/rgp/actions/runs/40767794459).

The three RGP SHA-256 digests matched the separately committed
[`corpus_preparation.json`](corpus_preparation.json). The Reader itself
was copied to a separate trusted location **only after its Git blob SHA-1
matched the pinned `python/rgp_reader.py` blob returned independently by the
GitHub connector** (`cb11bd04c346309c038c38e3e5accb540c341139`).
The Reader validated all three archives and returned complete snapshots:
46 RGP, 93 serde_json and 50 itsdangerous files. The same Reader's
`read()` method returned all 18 requested path accesses. All 13 *unique*
referenced files independently matched the Git blob SHA-1 values obtained
from the pinned GitHub `fetch_file` responses. The per-file anchors, source
URLs and both assistant answers are recorded in the JSON.

This proves source-content equivalence **for the selected files**, not
independent authenticity of arbitrary Actions artifacts or semantic indexing.

## Measured connector calls (one chat session)

| Component | Connector calls |
| --- | ---: |
| GitHub baseline: 12 tasks, 18 `fetch_file` reads | 18 |
| RGP artifact discovery: checkpoint + artifact listing | 2 |
| RGP acquisition: three artifact ZIP downloads | 3 |
| RGP Reader bootstrap: independently fetched pinned Reader source | 1 |
| RGP per-task `Reader.read()`: local, no GitHub connector | 0 |
| **RGP including acquisition** | **6** |

**Measured reduction in counted GitHub connector operations:
(18 - 6) / 18 = 66.67%.** For the `rgp_preparation_calls` field,
the two shared discovery calls and dedicated Reader setup call were allocated to `rgp`; total preparation
is six, independently of allocation. Failed operations and unrelated
development/CI/PR-management calls were not included in either arm.
Calls to run the local Reader are not GitHub connector calls.

## Interpretation and major limitations

- **Unblinded, non-independent evaluation:** the same assistant reviewed
  both arms' source and judged correctness. Correctness booleans are
  self-assessments against the 12 original rubrics, not external grading.
- **No cross-task GitHub cache reuse:** the baseline fetched files per task,
  even when a file was already seen. Across the 12 tasks only 13 source
  files are unique. Reusing those would lower the GitHub baseline to
  **13** retrieval calls, and the illustrative connector-call reduction
  would be **(13 - 6) / 13 = 53.85%**. This alternative was not separately
  executed; it is a lower bound under the stated zero-extra-fetch
  assumption, not a measured arm.
- **Evidence and visibility:** the chat tool history supports the counts,
  but is not exported as an independently authenticated trace. External
  `evidence_url` fields link to the pinned source, not a provider-signed
  call ledger. The evaluator checks shapes and totals, not the honesty
  of answers or tool-call logs.
- **No token, wall-clock, or byte-efficiency claim.** The current interface
  does not give comparable authoritative model token accounting, and
  no timings or model provider receipts were collected.
- **One repetition only:** no multiple-session, randomized, blinded or
  held-out comparison, and no separate reviewer.
- **No semantic index** is produced by this transport PoC.

The result is meaningful diagnostic evidence that this workflow can answer
the planned source questions using RGP while reducing repeated GitHub
connector operations. It does not justify releasing Gate B as GO without
an independent inspection of the source-linked answers, connector logs and
fairness of the retrieval/cache policy.
